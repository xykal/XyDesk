## Perubahan

### WH-01 — fallback GDI

- Alur baca/fallback dipisahkan ke helper yang dipakai implementasi Win32 dan fixture regresi. Tidak ada dynamic dispatch atau alokasi per frame tambahan dari trait tersebut.
- Setelah 15 frame dengan sampel gelap, perpindahan ke desktop-DC yang berhasil harus diikuti pengambilan frame sungguhan dan validasi panjang RGBA.
- Fallback gagal membuka DC tetap mempertahankan sumber lama dan frame lama yang utuh; kegagalan membaca frame dari DC baru dikembalikan sebagai error, bukan sukses palsu.
- Perubahan ukuran **atau posisi** capture rect saat fallback ditolak untuk meminta pembukaan ulang pipeline. Frame tidak boleh dikirim dengan encoder/input geometry lama.
- Konversi RGBA → NV12 sekarang mengembalikan `Result`. Buffer kosong, panjang salah, dimensi nol/ganjil, dan overflow ukuran ditolak sebelum output dimutasi.
- Pemanggil encoder NVENC meneruskan error tersebut. Test warna/conversion lama disesuaikan agar memeriksa hasil sukses.
- Timer peringatan GDI dipindahkan dari `static mut` ke state instance, supaya instance capture tidak berbagi state mutable tanpa sinkronisasi.

Fallback tetap tidak dapat menembus secure desktop, lock screen, atau isolasi user Windows. Frame gelap bukan bukti pasti bahwa sesi terkunci.

### WH-03 — standby dan ownership mutex

- Startup dan retry standby memakai `try_acquire(session, active_session)` yang memeriksa eligibility **sebelum** memanggil Win32.
- Akuisisi menghasilkan `LeaderGuard`, bukan boolean dan handle global atomik. Guard dipertahankan sepanjang fungsi host dan menutup handle saat keluar, termasuk jalur error.
- Mutex tetap memakai objek bernama dengan `bInitialOwner=false`; tidak memperkenalkan kepemilikan mutex berbasis thread yang bermasalah saat task async berpindah thread.
- Pesan standby membedakan kemungkinan sesi tidak berhak atau slot sibuk, bukan selalu menuduh sesi salah.

### WH-02 — tetap terbuka

Tidak mengubah namespace `Local`, ACL, path identitas/stepdown, atau startup HKCU. Dengan demikian patch ini **tidak** menjanjikan satu leader seluruh mesin atau takeover otomatis antar-user. Komentar modul leadership diluruskan; desain koordinasi lintas user memerlukan keputusan keamanan tersendiri.
