# Audit awal XyDesk — 27 September 2026

Baseline: `main`, `f5fd41f49ee0bd606cca8bd0bc0880c79c0a5318`.
Role: Docs & Audit — Sena - XySpace Team.
Sesi: `SESI-20260927-SENA-AUDIT`.

## Kesimpulan

Proyek sudah mempunyai implementasi remote desktop lintas komponen, bukan sekadar kerangka UI. Prioritas berikutnya adalah ketahanan sesi Flutter, cakupan gerbang CI, dan pembuktian capture/input/audio di Windows nyata. Audit awal ini belum cukup untuk menyatakan siap produksi, aman menyeluruh, atau memenuhi target latency gaming.

## Metode dan batas bukti

- Clone publik tanpa kredensial; pembacaan statis source, workflow, manifest, dan handoff.
- Tidak menjalankan build, test suite, layanan lokal, workflow Actions, pengujian endpoint produksi, atau akses akun.
- Tidak mengubah kode aplikasi, versi, secret, deployment, atau konfigurasi cloud.
- Angka test dan run yang disebut dokumen lama adalah laporan sesi sebelumnya, bukan hasil yang diverifikasi ulang pada sesi ini.
- Bukan audit seluruh baris kode, pentest, pemeriksaan riwayat Git lengkap, ataupun pemindaian dependensi terhadap advisory terbaru.

## Peta sistem yang ditemukan

| Area | Implementasi |
|---|---|
| Client | Flutter/Dart di `lib/`, WebRTC lewat `flutter_webrtc` |
| Web | Client React/TypeScript di `web/` |
| Host | Rust di `host/`, dependensi `webrtc`, OpenH264, integrasi Windows/NVENC |
| Panel distribusi Windows | C++ Win32 di `packaging/native-host/`; workflow mengompilasinya bersama engine Rust |

`host/Cargo.toml` masih memiliki target GUI Rust `xydesk`; keberadaan target tersebut tidak berarti paket Windows utama memakai GUI Rust. Jalur distribusi aktual terlihat di job `windows` pada `build.yml`.

## Temuan prioritas

### A1 — Tinggi: penolakan registrasi Flutter tidak ditangani secara spesifik

**Bukti:** `lib/webrtc/signaling_client.dart:144–209` menunggu `ch.ready`, menetapkan `_open = true`, lalu mengirim `hello` tanpa menunggu `welcome`. `lib/webrtc/rtc_service.dart:465–530` hanya menangani beberapa nilai `error`; `id sudah online` tidak ditangani. Pair dikirim setelah `connect()` kembali. Hub menolak ID duplikat di `cloudflare/src/hub.js:228–243`.

**Dampak bersyarat:** bila ID yang sama masih terdaftar, koneksi WebSocket dapat sudah terbuka tetapi registrasi aplikasi gagal. Client tidak menyajikan sebab sebenarnya dan dapat jatuh ke timeout pairing generik 20 detik. Bukan hang tanpa batas, karena watchdog tersedia.

**Tindak lanjut:** Client Flutter membuat status registrasi terpisah dari status transport, menunggu `welcome` dengan timeout, dan memperlakukan penolakan pra-welcome sebagai kegagalan registrasi. Retry harus terbatas/backoff dan tidak mengambil alih identitas aktif secara paksa. Uji ID duplikat, error pra-welcome, socket putus, timeout, serta cancel/reconnect. Temuan melanjutkan HANDOFF 25 September, bukan klaim temuan baru sepenuhnya. Belum direproduksi di APK/perangkat.

### A2 — Sedang: admin tidak terlihat masuk gerbang workflow

**Bukti:** tidak ada rujukan `admin/` pada berkas `.github/workflows/` yang diperiksa; `admin/package.json` menyediakan `test` dan `build`, tetapi tidak ada lockfile admin pada checkout ini. `web/` mempunyai `package-lock.json`.

**Dampak:** build penuh yang hijau belum membuktikan panel admin lulus test/kompilasi. Instalasi admin dari rentang versi tanpa lockfile juga kurang reproducible.

**Tindak lanjut:** role CI/Release menambahkan job admin (test + TypeScript/Vite), lockfile, dan instalasi deterministik. Pertahankan dispatch manual sesuai kebijakan pemilik. Audit ini tidak mengklaim dependensi tertentu rentan atau kadaluwarsa tanpa pemeriksaan advisory.

### A3 — Sedang: gerbang Rust Windows belum setara gerbang Linux

**Bukti:** `.github/workflows/build.yml:438–469` menjalankan fmt/clippy/test di Ubuntu. Job Windows pada baris 480–550 membangun engine MSVC release dan panel C++; bagian tersebut tidak menjalankan cargo test/clippy Windows.

**Dampak:** kompilasi Windows membuktikan kode dapat dibangun, bukan perilaku runtime capture/WASAPI/SendInput. Kelulusan test Linux tidak mencakup semua kode `cfg(windows)`.

**Tindak lanjut:** tambahkan test/clippy Windows yang sesuai, pisahkan test murni dari test yang membutuhkan desktop/perangkat audio. Runtime RDP/console/lock/unlock tetap memerlukan acceptance tersendiri, bukan sekadar tambahan unit test.

### A4 — Sedang: dokumen arah dan arsitektur tertinggal

**Bukti:** pembuka `ROADMAP.md:9–12` mengatakan belum ada loop inti, tetapi progres dalam dokumen yang sama mencatat loopback sudah terbukti. `docs/ARCHITECTURE.md:6,14,45–47` masih menyebut Tauri dan mencampur webrtc-rs dengan str0m, sementara manifest memakai crate `webrtc` dan workflow membangun panel C++. Baris 38 menjanjikan biaya nol selamanya. Komentar pembuka `build.yml` masih membicarakan PR/push, sementara trigger aktual hanya `workflow_dispatch`.

**Dampak:** kontributor berikutnya dapat mengambil keputusan dari keadaan lama. Target performa, roadmap codec, kemampuan aktual, serta bukti lapangan harus dipisah tegas.

**Tindak lanjut:** sinkronkan arsitektur dan ringkasan roadmap dengan source. Jangan menafsirkan DTLS-SRTP saja sebagai bukti perlindungan terhadap signaling server yang dikompromikan; klaim ancaman tersebut membutuhkan analisis autentikasi peer tersendiri. Jangan menjanjikan tarif layanan eksternal permanen.

### A5 — Rendah / hardening: Hub HTTP mengandalkan batas router

**Bukti:** `cloudflare/src/hub.js:82–126` melayani statistik/perangkat/kick tanpa validasi otorisasi internal pada cabang HTTP tersebut. `cloudflare/src/worker.js:61–74` memisahkan `/admin/` dan menolak path publik selain `/ws` setelah endpoint khusus.

**Penilaian:** tidak ditemukan jalur publik langsung ke `/kick` dari pembacaan ini. Ini kebutuhan defense-in-depth yang sudah dicatat HANDOFF 25 September, **bukan bukti bypass auth atau kerentanan publik yang berhasil dieksploitasi**.

**Tindak lanjut:** evaluasi kontrak otorisasi internal dan pengujian negatif lintas entrypoint bersama Backend/Edge. Jangan mengubah auth produksi tanpa persetujuan khusus.

### A6 — Operasional: durasi lab runner dapat memboroskan menit

**Bukti:** penutup `.github/workflows/test-lab.yml` menahan runner dengan loop tidur sampai durasi input, dibatasi 340 menit; tidak berhenti otomatis ketika skenario uji selesai.

**Tindak lanjut:** gunakan lab hanya untuk pengujian proyek yang terukur, tambahkan batas durasi yang sesuai dan exit saat pengujian selesai. Untuk pengujian interaktif panjang, pertimbangkan mesin Windows milik pemilik/self-hosted runner. Audit ini tidak menyatakan pelanggaran kebijakan GitHub telah terjadi, ataupun menentukan penyebab suspend akun sebelumnya.

## Release gate yang masih perlu bukti

1. Windows console dan RDP: gambar bergerak benar-benar sampai, bukan hanya ICE connected atau frame hitam yang berhasil di-encode.
2. Pergantian sesi aktif, disconnect/reconnect RDP, lock/unlock: perilaku dan pesan kegagalan sesuai batas keamanan Windows.
3. Keyboard/mouse fisik dan remote, resize/resolusi, input queue saat jaringan lambat.
4. Audio output/mic pada perangkat nyata; mesin tanpa audio harus melaporkan kemampuan dengan benar.
5. TURN terpaksa relay, bukan hanya koneksi LAN/direct; ukur throughput, loss, jitter, reconnect.
6. Latency glass-to-glass dengan metode terdokumentasi; jangan memakai angka encode saja sebagai latency total.
7. Jalur upgrade APK setelah penggantian signing key: HANDOFF 25 September mencatat signer berubah, sehingga kesinambungan update perlu keputusan distribusi yang eksplisit.

Changelog terbaru sendiri menyatakan perbaikan fallback RDP belum diverifikasi di desktop RDP Windows asli. Itu batas bukti yang wajib dipertahankan.

## Urutan kerja yang disarankan

1. Client Flutter: tutup A1 dengan regresi pada level protokol dan verifikasi APK lewat CI.
2. CI/Release: cakupan admin, lockfile, dan gerbang Windows; jalankan hanya setelah izin dispatch.
3. Host Engine + pemilik: acceptance Windows/RDP/audio/input dan pengukuran latency pada mesin nyata.
4. Docs & Audit: perbarui snapshot arsitektur, roadmap, dan handoff basi berdasarkan bukti baru.
5. Backend/Edge: hardening batas internal Hub setelah review desain otorisasi.

## Keamanan kredensial

Lampiran kredensial pemilik berada di luar repo. Tidak digunakan untuk clone maupun akses layanan dan tidak disalin ke laporan. Kredensial yang telah dibagikan sebaiknya dirotasi; konfigurasi publik seperti OAuth client ID tidak sama dengan client secret. Rotasi/revokasi tidak dilakukan otomatis karena dapat memutus produksi.

## Dampak pengguna dan status sesi

Audit tidak mengubah UI atau perilaku produk dan tidak membutuhkan screenshot produk. Hasil berupa daftar pekerjaan dengan batas bukti. Laporan dan catatan koordinasi hanya tersimpan lokal; tidak commit/push, tidak bump versi, tidak menerbitkan berita, dan tidak dispatch CI.
