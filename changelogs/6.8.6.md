# 6.8.6 — Latensi Terukur, Bukan Diklaim

**Tanggal:** 2026-09-28
**Tipe:** feat — pengukuran latensi end-to-end + rapikan repo

## Ringkasan Founder
Sejak awal tagline-nya "low-latency untuk gaming", tapi belum pernah ada satu angka pun yang membuktikannya selain foto layar. Rilis ini menaruh alat ukurnya langsung di produk: host menstempel waktu capture ke tiap paket video, browser membacanya per frame, dan panel Statistik menampilkan **"Layar ke layar"** — capture DXGI sampai frame dijadwalkan tampil. Laporan "lag" sekarang bisa datang dengan file JSON, bukan perasaan.

## Ditambahkan
- **Web — bagian "Latensi" di panel Statistik:** terima→tampil p50/p95/max dan jarak frame p95 per frame lewat `requestVideoFrameCallback` (`web/src/latency_probe.ts`). Tombol **Unduh laporan latensi** (JSON `xydesk-latency-report/1`, memuat codec/resolusi/jalur ICE/buffer/decode).
- **Host — RTP header extension `abs-capture-time`** (`host/src/abs_capture_time.rs`): NTP 64-bit dari `EncodedFrame.captured_at`, disisipkan di `video::tulis_frame` lewat `write_sample_with_extensions`. Didaftarkan di `Session::new`.
- **Web — `requestAbsCaptureTime()`:** Chrome membiarkan extension ini `stopped`; web mengubahnya ke `recvonly` sebelum `createOffer`. Begitu dinegosiasi, probe otomatis masuk mode *measured*.
- **APK — panel sesi:** baris **Buffer video** (delta `jitterBufferDelay`) dan **Decode / frame** (delta `totalDecodeTime`), paritas dengan web.

## Kompatibilitas
- Client/host lama tidak terpengaruh: extension hanya dikirim bila client menawarkannya di SDP. Firefox/Safari tanpa `setHeaderExtensionsToNegotiate` tetap dapat mode perkiraan (batas bawah, dilabeli).
- Angka "Layar ke layar" memuat selisih jam dinding host vs client. Negatif atau > 1 detik = NTP mesin melenceng, bukan codec.
