# 6.8.8 — Encoder Hardware AMD/Intel lewat Media Foundation

**Tanggal:** 2026-09-29
**Tipe:** feat host — jalur encoder kedua + kebersihan CI/rilis

## Ringkasan Founder
Sampai 6.8.7, PC tanpa GPU NVIDIA selalu jatuh ke encoder software (openh264,
15 fps di mode native). Rilis ini menambah jalur Media Foundation Transform:
encoder H.264 hardware AMD (AMF) dan Intel (Quick Sync) — juga NVIDIA lewat
driver Windows — dipakai otomatis bila NVENC tidak ada. Belum diuji di GPU
nyata (tim hanya punya sesi RDP); fallback ke openh264 dijamin tidak crash.

## Ditambahkan
- **`host/src/mft.rs` + `mft_setup.rs`** — MFT async (`MF_TRANSFORM_ASYNC_UNLOCK`),
  ICodecAPI low-latency, CBR, GOP 4 detik, tanpa B-frame; input NV12 CPU,
  output Annex-B dengan SPS/PPS di IDR.
- **`screen.rs::pick_hardware_encoder`** — satu pemilih untuk jalur WGC, GDI,
  DXGI: NVENC → MFT → openh264. `meta.encoder` kini `nvenc` | `mft` | `openh264`;
  preset otomatis client 6.8.7 sudah memperlakukan `mft` sebagai hardware.
- **`host-check.yml`** (manual) — fmt + clippy Linux dan clippy target Windows
  dalam 2-3 menit, untuk iterasi host tanpa Build penuh.
- **`release.yml` input `draft`** — rilis tanpa publikasi (tidak tampil ke
  publik, tanpa OneSignal, klien lama tidak melihat update).

## Diubah
- **Engine Rust dilink CRT statis** (`host/.cargo/config.toml`), menyamai
  panel C++ `/MT`: tidak lagi bergantung `vcruntime140.dll` di PC pengguna.
